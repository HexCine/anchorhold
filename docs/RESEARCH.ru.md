# Выбор AnchorHold

Проверено 21 сентября 2026. Рабочие допущения: один разработчик, небольшой бюджет,
без подтверждённой собственной аудитории. Задача — сделать полезный OSS-инструмент,
который имеет смысл сопровождать. Подписка по программе поддержки остаётся
возможным следствием реальной пользы, а не результатом количества репозиториев.

**Решение:** первая законченная версия проверяет устойчивость старых ссылок на
разделы документации. Отличие — обнаружение ситуации «адрес существует, но ведёт
к другому заголовку». Абсолютная уникальность не доказана; в исследованном наборе
решений не найдено такого же узкого готового процесса с сохранением baseline и
проверкой назначения адреса.

## Направления, проверенные до разработки

| Направление | Найденные решения / ограничения | Решение |
|---|---|---|
| Локальная CRD validation и pruning | [libkubara/crdvalidate](https://pkg.go.dev/github.com/kubara-io/libkubara/crdvalidate) использует upstream Kubernetes engine, покрывает pruning/defaulting/CEL | Не дублировать более полный существующий движок |
| Архив Git с submodules и export-ignore | [git-archive-all](https://github.com/Kentzo/git-archive-all) уже реализует основной сценарий, включая dry-run | Отклонено |
| Зависимости recording rules Prometheus | [pint rule/dependency](https://cloudflare.github.io/pint/checks/rule/dependency.html) проверяет удалённые зависимости и cross-group зависимости | Отклонено как прямой повтор |
| Граф переменных Grafana | [Grafana уже показывает зависимости](https://grafana.com/docs/grafana/latest/visualizations/dashboards/variables/inspect-variable/); есть [dashboard-linter](https://github.com/grafana/dashboard-linter/) | Узкий непокрытый сценарий пока не подтверждён; не утверждаем, что линтер покрывает любые циклы |
| Diff Sphinx objects.inv | [ubc intersphinx diff](https://ubcode.useblocks.com/usage/ubc_ci_cd.html), [sinv-textconv](https://docs.rs/crate/sinv-textconv/latest), sphobjinv | Простой diff уже существует; первоначальная идея отклонена |
| Смена назначения существующего permalink | [Sphinx #8709](https://github.com/sphinx-doc/sphinx/issues/8709), повторное воспроизведение на актуальной сборке | Выбран ограниченный эксперимент AnchorHold |

Проверялись web-поиск, первичная документация инструментов и GitHub issues/API.
Широкий поиск иногда выдаёт нерелевантные результаты; они не считаются
доказательством отсутствия аналогов. Сравнение ниже относится к рассмотренным
возможностям, а не ко всем инструментам в интернете.

## Три наиболее перспективных сценария

| Сценарий | Аудитория / цена проблемы | MVP и риски | Собственный проект или upstream |
|---|---|---|---|
| Стабильность permalink | Сопровождающие Sphinx/MkDocs/Docusaurus; внешние статьи и закладки открывают другую версию changelog | Локальные две HTML-сборки; ложные сигналы при обычном переименовании, hosting redirects за рамками | Малый независимый эксперимент оправдан; возможен перенос snapshot-проверки в lychee |
| CRD upgrade preflight | Авторы операторов и SRE; schema changes могут влиять на сохранённые данные | Сложная семантика API server/CEL/conversion webhooks; Python-копия опасно неполна | Существующий upstream Go engine предпочтительнее |
| Inventory diff | Авторы Python-документации; замечать удалённые intersphinx-символы | Сделать легко, но это уже реализовано; plain diff не доказывает смену смысла адреса | Использовать существующий ubc/sphobjinv, не делать дубликат |

Это инженерные оценки, не вероятности получения поддержки.

## Подтверждение проблемы и состояние исправлений

[Sphinx #8709](https://github.com/sphinx-doc/sphinx/issues/8709) открыт на дату
проверки. Issue описывает неустойчивые числовые идентификаторы разделов.
Прочитаны body, comments и полный timeline; связанных PR в cross-reference
событиях этой выдачи не найдено. Это не доказывает, что работа не ведётся в другом
месте. В комментариях есть рабочие обходы: явные targets, заголовки с буквенным
префиксом, конфигурация id-prefix. Комментарии также упоминают несколько
затронутых проектов; каждое из этих утверждений отдельно нами не воспроизводилось.

[pip #8152](https://github.com/pypa/pip/issues/8152) **закрыт 2 апреля 2021**.
Его body и timeline проверены. Это историческое подтверждение последствий,
не текущая неисправность pip и не «свободная задача без решения».

Наш собственный минимальный RST changelog собран Sphinx **9.1.0**, docutils
**0.22.4**. В первую сборку вошли 3.2.0, 3.1.0, 3.0.0; во вторую сверху добавлен
3.3.0. Старые `id1`, `id2`, `id3` остались, но теперь соответствуют другим версиям.
AnchorHold нашёл три `heading_retargeted`; точные результаты сохранены в
`examples/reports/sphinx-9.1.0.json`. Исполнялась только наша минимальная
конфигурация сборки, команды из чужих issues не запускались.

## Проверка отличия от существующего инструмента

[Lychee](https://lychee.cli.rs/guides/cli/) умеет проверять fragments, локальные
файлы и remap. Это полезные возможности; обычную проверку битых ссылок повторять
не нужно. Здесь проверяется другое свойство: сохранился ли прежний заголовок
по историческому адресу.

На три старые ссылки в новой Sphinx-сборке выполнено:

```text
lychee --offline --include-fragments=anchor-only --no-progress after/html/backlinks.html
```

Результат **lychee 0.24.2: 3 OK, 0 Errors, exit 0**.
Результат **AnchorHold: 3 heading_retargeted, exit 1**.

Бинарник взят из [официального release](https://github.com/lycheeverse/lychee/releases/tag/lychee-v0.24.2),
Windows amd64 ZIP сверён с SHA-256 из release metadata:
`32975d1493ee1a975d6bb41e4fb56fe419cb442ded628bb772ba2e614acfacad`.
Бинарник не включён в выпуск AnchorHold. Сравнение не означает, что lychee
работает неправильно: существование адреса и устойчивость его назначения —
разные проверяемые свойства.

Простое сравнение objects.inv тоже не выбрано: [ubc](https://ubcode.useblocks.com/usage/ubc_ci_cd.html)
уже умеет diff, а [sinv-textconv](https://docs.rs/crate/sinv-textconv/latest)
обслуживает git diff. [sphinx-linkfix](https://pypi.org/project/sphinx-linkfix/)
переписывает GitHub-style ссылки при сборке, не хранит историю назначения
публичных адресов. Эти инструменты изучались по документации; выполнялся только
прямой сравнительный прогон lychee.

## Польза, ограничения спроса и путь к пользователям

Есть воспроизводимый класс ошибки; **внешних пользователей AnchorHold пока нет**.
Смена текста может быть намеренной, одинаковые заголовки неоднозначны. Поэтому
диагностика требует проверки и не предлагает автоматически перенаправлять URL.
Статический снимок также не моделирует серверные redirects и JS-приложение.

Первая аудитория: сопровождающие changelog и технической документации, меняющие
генератор, тему или структуру разделов. Предлагать стоит воспроизводимый отчёт на
их добровольно предоставленных старой/новой сборках, а не просьбу поставить звезду.
Никаких сообщений или PR другим людям в рамках этой работы не отправлено.

Для одного разработчика стоимость исполнения локальная, обязательной AI API
или инфраструктуры нет. Цена сопровождения — точность heading association,
разные шаблоны HTML, разбор ложных срабатываний. Если сопровождающие предпочитают
один линтер, разумнее предложить перенос полезного snapshot-процесса в lychee,
чем поддерживать отдельный репозиторий ради статуса владельца.

Будущую заявку в OSS-программу должны поддерживать независимое повторное
использование, реальные исправления и история сопровождения. План проверки этого
на 30 дней — в ROADMAP.md. Гарантии подписки или выдуманной статистики нет.
